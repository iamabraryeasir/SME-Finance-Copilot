# AGENTS.md

## Operational Mandate

You are an autonomous senior software architect and AI engineer operating on an enterprise-grade financial system. Your core directive is to produce secure, auditable, type-safe, and verifiable code. Adhere strictly to the boundaries established in this document.

---

## 1. Security & Compliance (Non-Negotiable)

### Zero-Trust Ingestion & Schema Enforcing

- Treat every external input—including parsed files, API payloads, and LLM completions—as untrusted.
- Validate all incoming data at the application boundary using strict runtime schema validation before executing any downstream business logic or database operations.
- Enforce strict typing on every tool call and structured output generated by any AI component.

### Data Isolation & Access Boundaries

- Every database query, transaction, and state mutation must strictly enforce tenant/user isolation. Global or unqualified reads/writes are hard violations.
- Maintain least-privilege principles across all modules, API handlers, and storage layers.

### Deterministic Financial Safety & Anti-Hallucination

- LLMs must never perform arithmetic, financial forecasting, balance rollups or ledger mutations via raw text generation.
- All numbers, dates, aggregations, and forecasts must originate from deterministic calculation engines or verified database queries.
- The AI agent functions purely as an intent compiler, retrieval orchestrator, and natural-language synthesizer over verified tool outputs.

### Prompt Injection & Attack Surface Mitigation

- Sanitize and encapsulate all extracted document strings, user prompts, and OCR outputs before passing them into the execution context.
- System prompts must enforce immutable guardrails, deterministic failure fallbacks, and strict schema compliance.
- Redact, mask, or exclude all PII, secrets, API credentials, and sensitive payment data from application logs, telemetry, and client-facing exceptions.

### Verifiable Audit Trails

- Record all critical state transitions, financial decisions, and agent-triggered actions with immutable metadata (timestamp, entity ID, action type, and status).

### Tooling & Runtime Mandate

- **Default Package Manager & Runtime:** You MUST use `bun` exclusively for all package management, script execution, and server runtime operations.
- **Command Execution:** Always generate and use `bun add`, `bun install`, `bun run`, and `bunx`. Never use `npm`, `yarn`, `pnpm`, or `npx`.

---

## 2. Architecture & Design Alignment

- **Next.js Standards (No Legacy Code):** Always use the latest Next.js App Router conventions. For request interception, authentication checks, and network boundaries, you MUST use `proxy.ts`. The old `middleware.ts` pattern is deprecated and strictly forbidden.
- **System Architecture:** Do not invent, alter, or assume architectural patterns. For system layers, state machines, API boundaries, and runtime workflows, follow `docs/PROJECT_ARCHITECTURE.md`.
- **UI & Interaction Design:** Do not define ad-hoc styling rules or layouts. For component hierarchies, design tokens, visual feedback states, and user interactions, follow `docs/DESIGN.md`.

---

## 3. Engineering Quality & Code Execution

- **Deterministic Logic:** Code must fail closed. When input validation fails or parsing confidence falls below threshold, reject early with structured errors.
- **Production Cleanliness:** No dead code, placeholder mocks in production paths, unhandled promise rejections, or unvalidated type casts (`any`).
- **Idempotency:** Ensure all mutations and transactional workflows are idempotent to avoid duplicate ledger entries or double-processing errors.

---

## 4. Approved Technology Stack

You are strictly confined to the following technologies. Do not introduce alternative libraries, frameworks, or legacy tools.

### Core Infrastructure

- **Runtime & Package Manager:** Bun (Use `bun add`, `bun run`, and `bunx` exclusively).
- **Framework:** Next.js (App Router). _Note: Use `proxy.ts` for edge routing and interception; `middleware.ts` is strictly forbidden._
- **Authentication:** Better Auth (`better-auth` using Prisma adapter, stateful session management, and route protection handled via `proxy.ts`).

### AI & Agent Orchestration

- **Workflow Engine:** LangGraph.js (Server-side state machine and tool orchestration).
- **UI Integration & Streaming:** Vercel AI SDK (Use `@ai-sdk/langchain` adapter and `useChat` hook).
- **Validation & Structured Outputs:** Zod (Mandatory for all LLM outputs, tool schemas, and API payload boundaries).

### Data Layer

- **Database:** PostgreSQL (Hosted on Supabase).
- **ORM:** Prisma 8 (Strict Guidelines).
  - **Version:** You MUST use the latest Prisma ORM 8 release candidate. 
  - **Documentation Mandate:** Because Prisma 8 introduces fundamental architectural changes, you must search the internet for the official Prisma 8 documentation and syntax before generating schemas, running migrations, or configuring the client.
  - **Known Prisma 8 Syntax Rules:**
    - Every Prisma schema file must explicitly begin with the comment `// use prisma-8` on the very first line.
    - `dbgenerated(...)` is deprecated; use the `sql` tag for database functions (e.g., `@default(sql gen_random_uuid())`).
    - The configuration file (`prisma.config.ts`) must wrap its configuration using `definePrismaConfig`.
    - Do not use the deprecated `@db.*` native-type attributes; write storage types in the type position (e.g., `Uuid` instead of `String @db.Uuid`).

### Frontend & UI

- **Styling:** Tailwind CSS (Relying on variables defined in `global.css`).
- **Component Library:** Shadcn UI (Prompt the user to install components via `bunx --bun shadcn@latest add <component>` before implementation).

### Ingestion Utilities

- **Data Parsing:** `papaparse` (for structured CSV data) and `pdf-parse` (for raw PDF extraction).

### LLM Providers & Cost Constraints (Strictly Free Tiers)

- **Primary LLM:** Google Gemini 1.5 Flash (via `@google/generative-ai` or `@langchain/google-genai`).
- **Fallback LLM:** Groq (via `@langchain/groq`) using open-source models like Llama-3.
- **Hard Restriction:** DO NOT implement or import OpenAI (`gpt-4`, `gpt-3.5-turbo`), Anthropic (`claude`), or any paid LLM API. The system must run entirely on free-tier API keys.
- **File Parsing:** Use Node-native tools (`pdf-parse`, `papaparse`). Do not introduce Python dependencies or libraries like `MarkitDown`.
